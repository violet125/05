# 在扣子（Coze）搭建“听见行动”

交付内容为可复制的配置与搭建方案，不是已经发布的扣子智能体，也不是可直接导入的工作流文件。具体入口名称、模型与插件可用性以你的扣子版本和账号为准。

## 1. 创建智能体

创建一个对话型智能体，填写：

名称：听见行动

简介：为视障与低视力用户解读图片、菜单、账单、邮件和表格，把信息变成适合朗读的简短行动步骤。

人设与回复逻辑：从同目录《听见行动-Agent配置.md》中复制“系统指令”标题之后、“推荐开场问题”之前的全部内容。

开场白：你好，我是听见行动。你可以发一张图片、一段文字或一份文件，告诉我想完成什么。我会先讲重点，再一步一步说明。

预置问题：

- 帮我读菜单，找出50元以内的主食。
- 帮我辨认显示器接口的位置。
- 整理这些邮件中需要处理的事。
- 分析筹款表的总额和异常记录。

## 2. 配置可用能力

选择账号内可用的支持图片理解的模型，并用实际上传图片验证。不要仅凭模型名称假定已支持图片。

按以下顺序搭建最小可用版本：

1. 图片任务：允许用户在对话中上传图片，交给支持视觉输入的模型处理。若当前发布渠道不传图片，需更换支持的渠道或接入图像理解工具。
2. 邮件任务：第一版由用户粘贴正文，智能体提取待办、期限与来源，不需要邮箱权限。
3. 文件任务：添加当前平台可用的文件读取能力。验证PDF、CSV或XLSX是否确实受支持；截图与扫描PDF需要图像理解或OCR。
4. 表格任务：添加可执行计算或数据分析的工具。确认能拿到真实单元格数据，保留工作表、字段与行号。不要仅把完整表格切成知识库片段后依赖检索结果求总额。

这里描述的是所需能力，不指定未经核实的插件名称。选择插件前检查权限、支持格式和数据处理说明。

## 3. 第一版不要强制使用工作流

可先用“对话智能体＋视觉模型＋文件读取＋计算工具”完成测试，降低搭建成本。由系统指令根据输入决定直接回答、读取文件或计算。

需要固定业务流程时，可按下面逻辑配置工作流；这是设计草图，不是导入JSON：

开始（用户问题、附件）
→ 检查输入与实际工具能力
→ 分类（图片／邮件协议／表格／写作）
→ 图片理解或正文读取或表格解析
→ 必要时计算
→ 生成结论、下一步、待确认信息与来源
→ 返回适合读屏的文本

失败分支：缺附件时请求对应材料；读取失败时说明失败并给可用的替代输入方法；不支持工具时不声称已完成。图片分支需传实际图片输入，不能只将本地文件路径当成可访问图片。

## 4. 语音与邮箱扩展

语音：先确认目标发布渠道是否支持语音输入和播报。若不支持，需要额外的语音转写与合成服务以及能播放音频的前端。实时双向语音与打断并非靠提示词就能实现。测试读屏软件能否读取控件名称，能否用键盘暂停播报。

邮箱：后续通过平台支持的授权连接或自建服务接入；第一阶段只读。限制邮件检索范围，保留邮件主题、发件人和日期。用户不应在聊天框粘贴邮箱密码或密钥。发送功能与读取分开，实际发送前必须展示收件人与正文并取得明确授权。

摄像头：上传照片不等于实时视觉。连续摄像头辅助需要发布端提供取帧、时间戳与用户开启关闭控制，不能只用人设提示词宣称具备。

知识库：可添加经过核对的产品说明、组织服务介绍与无障碍操作文档。不要默认将私人邮件或上传账单存入公共知识库；具体存储期限与权限需要根据实际平台设置确认。

## 5. 调试与发布

先在预览对话里执行《听见行动-验收清单.md》的12个用例。对实际发布渠道再次测试图片上传、文件传递、语音、键盘和读屏操作，预览成功不代表所有渠道都支持相同功能。

第一版发布描述可直接使用：

“听见行动可以解读你提供的图片、文字和文件，整理成便于朗读的重点和操作步骤。邮件请先粘贴正文；语音与文件支持情况取决于当前渠道。图片描述不能替代实时道路安全判断。”

只有实际接入并验证之后，才在介绍中加入邮箱自动检索、语音播报或实时摄像头功能。

建议先设为私人或小范围试用。通过验收后由账号所有者选择发布范围，明确用户材料的用途与保留规则。
